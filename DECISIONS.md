| 16 | 2026-07-28 | `vwAttendanceRegister` returns one row per employee per date, not a pivoted day-1..day-31 matrix | A view cannot have a dynamic column count. | 17 | 2026-07-28 | `vwDailyTurnout` derives present/absent from `ops.Attendance` rather than from the `ops.Turnout` snapshot | The live turnout board must be correct before a supervisor files the turnout register. `ops.Turnout` remains as the filed record for audit and reporting | — |
| 18 | 2026-07-28 | `300_functions.sql` drops every function and code-generator procedure in reverse dependency order before creating them | `CREATE OR ALTER` cannot alter a `WITH SCHEMABINDING` function that another schemabound object binds to (Msg 3729). | 19 | 2026-07-28 | Password verification happens in C#, not in SQL. `usp_User_Login` is split into `usp_User_GetForAuthentication` + `usp_User_LoginSucceeded` / `usp_User_LoginFailed` | PBKDF2 at 210 000 iterations cannot run in T-SQL. | 20 | 2026-07-28 | Result-set contract: command procedures return one envelope row; read procedures return data (plus a `TotalRows` set when paged) | Matches `IDbExecutor.QueryEnvelopeAsync` / `QueryPagedAsync` in `02-api.md` §3.1, so the C# side needs exactly two call shapes | `01-database.md` §7 |
| 21 | 2026-07-28 | `520_procedures_operation.sql` is split by domain: 520 attendance, 521 deployment, 522 patrol/location, 523 people, 524 incident/complaint, 525 inventory/HR | The spec's single file would run to several thousand lines, which is unreviewable and hostile to AI-assisted editing. Numeric ordering and the run sequence are unchanged | `01-database.md` §0 and §7.2 |
| 22 | 2026-07-28 | `MERGE` is not used where concurrent writers are possible | MERGE has documented concurrency defects against unique indexes. Bulk attendance marking uses explicit `UPDATE` then `INSERT` with `UPDLOCK, HOLDLOCK`. MERGE is retained only in the single-threaded summary-refresh job | — |
| 23 | 2026-07-28 | Geofence distance, worked hours and attendance status are computed in the procedure, not accepted from the client | The phone can trivially forge a distance value. `docs/prd/01-database.md` §6 proposed an INSTEAD OF trigger; computing in the procedure is faster on a high-volume table and keeps IDENTITY/OUTPUT semantics simple. `600_triggers.sql` will add an AFTER trigger that validates rather than computes | `01-database.md` §6 item 2 |
| 24 | 2026-07-28 | `600_triggers.sql` uses AFTER triggers that validate; it does not use INSTEAD OF triggers to compute values | An INSTEAD OF trigger on `ops.Attendance` breaks `SCOPE_IDENTITY()` and `OUTPUT` semantics on a high-volume IDENTITY table. Computation lives in the procedures; the trigger is a backstop that rejects any write lacking a server-computed distance | `01-database.md` §6 item 2 |
| 25 | 2026-07-28 | Seeded users carry `LegacyPasswordHash = 'PLAINTEXT:<password>'` | PBKDF2 at 210 000 iterations cannot be computed in T-SQL, so the seed cannot produce a real hash. The API accepts this prefix **only** when `ASPNETCORE_ENVIRONMENT=Development` and immediately re-hashes on first login. It must be rejected outright in staging and production | — |
| 26 | 2026-07-28 | Demo seed is deterministic: values derive from `EmpID` and date arithmetic, never `RAND()` or `NEWID()` | Screenshots, tests and payroll golden-files must be reproducible across machines and reruns | `01-database.md` §8.3 |
| 27 | 2026-07-28 | `711_seed_demo_tenant.sql` supersedes `710_...`; `run-all.ps1` skips 710 via an `$Exclude` list | 710 used `sys.all_objects` under `CROSS APPLY` to generate row numbers. That is a metadata view whose cost scales with the object count, and after the migration created ~350 objects the seed appeared to hang. Replaced with literal `VALUES` lists. 710 could not be edited in place because a Windows process held a file lock; delete it and drop it from `$Exclude` when convenient | — |
| 28 | 2026-07-29 | Legacy V1 controllers: kept `LegacyControllerBase` + `UsersController`/`OperationController`/`TasksController`/`SalesController`/`ReportController`; emptied the parallel `Legacy*.cs` set | Two implementations were written in parallel. The kept set covers 127 endpoints against 90, is a strict superset, and factors the envelope helpers into a base class. The superseded files are emptied rather than deleted because the sandbox cannot remove host files - delete them when convenient | — |
| 29 | 2026-07-29 | `TreatWarningsAsErrors` is false until the solution builds clean | ~7,100 lines were written without a compiler available. Leaving it on buries the handful of real errors under hundreds of nullable warnings. Turn it back on once green | `Directory.Build.props` |
| 30 | 2026-07-29 | Every section of `720_seed_demo_transactions.sql` guards on **its own table**, not on a single script-wide flag | The old guard was `IF EXISTS(ops.Attendance) ... RETURN`. `RETURN` exits only the *current batch*, so on a rerun every later batch still ran; and on the first run a syntax error in batch 4 aborted sqlcmd (`-b`) after attendance and turnout were already committed. The result was a half-seeded database that looked "already seeded" forever. Per-section guards make the script resumable: run it again and it fills only what is missing | — |
| 31 | 2026-07-29 | Reserved-word scan now covers **CTE names and aliases**, not just table and column names | A CTE named `plan` (`WITH ... plan AS (...)`) is a syntax error because `PLAN` is reserved - the same class of bug as `org.[Plan]` in decision-era 020, but invisible to a scanner that only looked at DDL. `db/scripts` is now clean under the widened scan | — |
| 32 | 2026-07-29 | `DbExecutor` discovers each procedure's real parameter list with `SqlCommandBuilder.DeriveParameters`, cached per process | 27 of the 150 procedures do not declare `@UserID`; injecting it unconditionally produced "Procedure has too many arguments specified" and a 500 on `masters/bootstrap`. Deriving the signature is self-maintaining - add a parameter later and the executor picks it up with no code change. Cost is one extra round trip per procedure per process lifetime | `02-api.md` §3 |
| 33 | 2026-07-29 | The web app never holds the refresh token in JavaScript. Next.js route handlers (`/api/auth/login|refresh|logout`) act as a BFF and put it in an httpOnly, Secure, SameSite=Strict cookie; the access token lives in a module variable | A 30-day rotating refresh token in `localStorage` is XSS-lootable, and this tenant's data is payroll, GPS traces and selfies. With this split the worst an injected script can take is a 15-minute access token. Cost: a page reload has no token until one silent `/api/auth/refresh` returns, so `AuthProvider` gates rendering on `ready` | `03-web.md`, `05-rbac-and-nfr.md` S3 |
| 34 | 2026-07-29 | `createApiClient` takes a `refreshAccessToken()` callback instead of reading a refresh token from the token store | The web keeps the refresh token in a cookie and the mobile app will keep it in the device keychain. Making the client ask "get me a new access token" rather than "here is the refresh token" lets one client serve both without knowing where the secret lives | `packages/shared/src/client.ts` |
| 35 | 2026-07-29 | `useAuth().has()` checks the permission list only; it no longer returns true for COMPANY_ADMIN and SUPER_ADMIN by role | The server is the authority. Short-cutting by role meant that revoking a permission from an admin role still left the button on screen, so the user would click it and get a 403 instead of not seeing it | — |
| 36 | 2026-07-29 | Dark mode is handled by `next-themes` with `attribute="class"`, not by hand-rolled `localStorage` + `classList.toggle` | The hand-rolled version in `app-frame.tsx` flashed light on every load because it ran in an effect, after paint. next-themes injects a blocking script that sets the class before first paint | `03-web.md` §1.1 |
| 37 | 2026-07-29 | Added `usp_Client_GetList`, `usp_Advance_GetList` and `usp_Receipt_GetList` in `561_procedures_lists.sql` | These three tables had Save/Insert/Approve procedures but no way to read a page of them, so the web app had no client list, no advances screen and no receipts screen. | 38 | 2026-07-29 | A spoofed GPS ping is **recorded and flagged**, not silently discarded | `usp_Location_Track` returned "Mock location ignored" and wrote nothing, and the batch procedure filtered mock rows out, so `ops.LocationLog.IsMockLocation` was always 0 - a dead column, and no evidence that anyone had tried. Now the ping is stored with the flag set; `usp_Location_GetLive` excludes flagged rows from the last-known position but shows a `MockPingsToday` badge, and `usp_Location_GetTrail` returns them marked with `SegmentMeters = NULL` so a fake point cannot inflate distance travelled. | 39 | 2026-07-29 | `POST /api/v2/tracking/ping/batch` accepts a batch containing spoofed pings rather than rejecting the whole batch | An offline-first client uploads a shift's worth of history at once. Failing the batch on one bad row would discard genuine data to punish a single ping. The reply reports how many were flagged | `02-api.md` |
| 40 | 2026-07-29 | `tools/check-routes.mjs` runs in `pnpm check` and fails if the web app calls an API route that does not exist | TypeScript cannot check a URL - it is just a string. The payroll screen posted to `/payroll/runs/validate` when the API exposes `GET /payroll/validate`; it typechecked cleanly and would have shipped as a 404 that only appeared when someone clicked "Validate". A `${...}` hole matches any single segment, so `/recruits/${id}/${action}` is accepted while a wholly literal wrong path is not | — |
| 41 | 2026-07-29 | The web BFF has no "ignore TLS certificate errors" switch | The first draft had one behind an env var. It would have been useful exactly once and then sat in the codebase waiting to be switched on in production. `dotnet dev-certs https --trust` is the fix; if the API is unreachable the route handlers return a 502 that says so in as many words | `apps/web/src/lib/server-api.ts` |
| 42 | 2026-07-29 | List screens are built from a shared `ResourceList` rather than hand-written per screen | The first screens were each ~120 lines of the same five blocks - header, filters, skeleton, table, pagination - and every copy was a chance for one to drift: a missing error state, a page size that ignored the URL, a spinner where a skeleton belongs. | 43 | 2026-07-29 | One `<Status>` component owns the status-to-colour mapping for the whole app | Left to each screen, "Overdue" ends up amber on one list and red on another, which teaches users that the colours mean nothing. | 44 | 2026-07-29 | `/reports` is one shell for all 21 report keys, with columns inferred from the first row | Each report is a different procedure returning a different shape. | 45 | 2026-07-29 | OTP verification returns a signed ten-minute reset token, not the user id | `usp_User_VerifyOtp` returns a UserID and the old controller passed it straight back to an anonymous caller. | 46 | 2026-07-29 | `POST /api/v2/auth/password/reset` revokes every existing session for that user | Whoever asked for the reset may be locking someone else out deliberately - a departing employee, a shared handset. Leaving the old sessions alive would defeat the point of the reset | — |
| 47 | 2026-07-29 | Nav entries carry a `permission` code and are filtered client-side by the user's actual permission list | Showing a Payroll link to a supervisor who gets a 403 on click teaches people that the product is broken. | 48 | 2026-07-29 | Demo credentials are prefilled on the sign-in form only when `NODE_ENV === "development"` | A production build must never ship a login form that arrives with a working username and password already typed into it | `apps/web/src/app/login/page.tsx` |
| 49 | 2026-07-29 | Every field write on mobile goes into the SQLite outbox FIRST, then flushes; nothing calls the API directly | A guard who punches in at 06:00 in a basement car park and surfaces at 14:00 must have a 06:00 punch. | 50 | 2026-07-29 | A `DUPLICATE_PUNCH` reply is treated as SUCCESS by the sync engine, not as an error | It means an earlier attempt reached the server and only the response was lost. | 51 | 2026-07-29 | A 4xx other than 409 stops retrying immediately and surfaces in the Sync Centre | A rejected geofence or a malformed payload fails identically on every attempt. Retrying it for 24 hours burns battery and hides the real problem from the one person who can fix it | — |
